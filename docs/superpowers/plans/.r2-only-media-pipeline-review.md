# R2-only media pipeline review ledger

- Task 1 ruling: keep legacy `stream-source-token.ts` and `stream-source.ts` source files temporarily until Stream-dependent workflow code is removed in later tasks; they are no longer mounted in the active app. This avoids breaking compilation mid-migration while preserving the spec's final no-Stream requirement.
- Task 1 review: new media token preserves exact HMAC/project/key/expiry binding; new route checks token, current project source identity, HEAD, and byte-range R2 delivery.
- Task 2 review: active dubbing workflow constructs `R2SourceMediaService`; prepared source is a signed R2 URL; Deepgram duration metadata is admitted only when finite and positive; pipeline stage names no longer mention Stream.
- Task 3 ruling: use Mediabunny `AppendOnlyStreamTarget` with fragmented MP4 rather than positional `StreamTargetChunk` writes. The approved spec explicitly prefers append-only streaming when supported, and Mediabunny documents `fastStart: 'fragmented'` as monotonic append-only output. This removes random-write complexity and maps directly to sequential R2 multipart upload while preserving bounded memory/backpressure.
